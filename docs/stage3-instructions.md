### 6.3 一日の流れの案(利用者の決定 1)

`plans` を、**日ごとの一日の流れ**に変える(項目の追加だけ。今ある `main`・`adds` は残し、山だけのときの中身は変えない)。

- 案は「日」が単位。中に、時刻の順に並んだ枠を持つ: **朝〜日中(山)→ 日中(生き物。段階 4 で入れる。今回は空の枠だけ)→ 夜(星)**。枠の順番はコードが決め、AI に並べ替えさせない。
- 山に添える星: **同じ日の夜**(山の日 = 夜の始まりの日)で、条件を通った地点のうち、山から直線 `combo.near_km`(20。仮置き)以内のもの。複数あれば、ホシビヨリの順位(主軸の地点を先 → `rank`)→ 山からの直線距離の近い順 → `site_id` の順で 1 つ(残りは件数だけ)。**近くに星の地点が無い山には付けない。**
- 前の夜(前泊)の星は、今回は作らない(報告書の「決めてほしいこと」に入れる)。宿・山小屋の名前や営業は書かない。
- 星が主役の質問(興味の語が星・夜の質問)のとき: 夜の星の地点を起点にし、その地点から直線 `combo.near_km` 以内の、同じ日に主役にできる山を「日中」の枠に入れる。答えの中の順番は、それでも時刻の順(日中 → 夜)。
- 案どうしの並び: 日付 → 起点の並び。山が起点の案は今の山の並び(点数 → 危険信号の軽さ → 直線距離 → ID)のまま。星が起点の案はホシビヨリの順位 → 出発地からの直線距離 → `site_id`。**山の点数と星の順位・スコアを比べて並べない。** 山が起点の案と星が起点の案の両方があるときは、質問の興味の語に合うほうを先にする(仮置き)。
- 主役・添えものにしない条件: 山は今までどおり。星は、条件を通っていない夜・雲量を調べていない夜・`site_id` が `null` の地点。
- 「夜」の枠に書けることは、資料にある事実だけ(晴れ間の時間帯・月の無い時間・どちらのモードか)。**どの星・惑星が見えるかを、AI の知識で書かせない**(5.1 で JSON に無いと分かった場合)。
- 開発指示書 6.3 を、この決まりに合わせて書き直す(「山(昼)+ 星(夜)」の行、並びの文。「泊まりにすると」の案は今回作らないと書く)。12 章に 1 行足す。

### 6.4 答えの形・足りないもの・見送る夜

- 答えのおすすめは、案ごとに **時刻の順で書く**(朝〜日中の山 → 夜の星)。`docs/answer-voice.md` に手本を足す(山と星がそろった日・星が付かない日・星が起点の日)。山だけの手本は変えない。
- 聞かれた夜の雲量が棚に無い(調べていない・予報の範囲の外)ときは `gaps` に入れ、答えに「その夜の雲の予報は今回調べられていません」と出す。「条件を通らなかった」と混ぜない(件数が嘘になるため)。
- 条件を通らない夜(月・雲など)は、山の見送りと同じ作りで、夜ごとのまとめの文を資料が用意する。理由の語は 5.1 で確かめた語だけ。**山と星の件数を 1 つの文・1 つの事実に混ぜない。**
- 予報の区分が ECMWF の夜は、山の「信用してよい範囲の外」と同じ扱いで、確かさを下げる決まった文を付ける(文は、ホシビヨリの `AGENTS.md`・画面にある言い方から取る)。
- `requires_lift_access` が true の地点は、運行を確かめていないことを決まった文で必ず付ける(外さない。仮置き)。
- 星の棚が無い・検査に通らないときは、止まらずに山だけで答え、「星の予報は今回使えませんでした」と 1 文で書く。
- 字数の上限 2,000 字は変えない。超えるときに削る順番は、今の決まりに合わせる。

## 7. 第 3 部: 通しの試しと報告書
