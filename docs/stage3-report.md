## 6. 確かめられていないこと

- **GitHub のマシンでの星の所要時間・通信の回数・429**(U1・U2・U3)。天の川の 583.2 秒は全部が計算なので、マシンの速さで変わる。天文計算の保存が無い 1 回目は、星空・星座モードも計算が増える(実測では 1960 件のうち 425 件だけ計算した)。
- **天文暦の取得先**: Skyfield 1.55 のコードでは `ssd.jpl.nasa.gov`。転送先が別のホストなら計測フックが止める(最初の手動実行で分かる)。GitHub で入る Skyfield の版が違えば、取得先が変わりうる。
- **計測フックの「壁時計の飛び」の検査(300 秒)**: 天の川モードは計算が長いので、途中で通信が要る回(1 回目のモードで取れなかったセルがある回)は、通信のあいだが 300 秒を超えて中止になりうる(`suspend_suspected`)。実測の回は通信 0 回で当たらない。当たれば星は前回のまま。
- Python 3.13 でのホシビヨリの通し実行(ホシビヨリ側で未確認)。`requirements.txt` が GitHub のマシンで入るか。
- 天の川モードが選ばれる季節の答え(見本の季節は 0 件。作り物の見本で、モードが変わることだけを確かめた)。
- 近日中(MSM)の候補の夜がある日の `finals` の順位(実物の `finals` は 0 件)。
- 実物に無かった種類: `window_kind: none`・`status: not_examined`・`site_id: null`・`window_kind: moon_free` で通信に失敗した夜。**見本には作らず**、テストの中の作り物で確かめた。

## 8. 決めてほしいこと

1. **前の夜(前泊)の星の案を作るか。** 今は同じ日の夜だけ。→ 決まるまで作らない。
2. **山が起点の案と星が起点の案の先後。** 今は、星の語だけなら星が先、山の語もあれば山が先。
