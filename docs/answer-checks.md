# 照合(`concierge verify`)の検査の一覧

`verify <下書き> --brief <id>` が下書きを資料と照らす。1 つでも当たれば不合格(終了コード 1。標準エラーに文ごとの理由と直し方)。
書き直しは 2 回まで(`config.yaml` の `answer.max_rewrites`)。3 回目も不合格なら、資料から作った控えの文を出す(終了コード 0)。
語の一覧と値は `concierge/data/verify.yaml`(**どれも仮置き**)。コードは `concierge/verify.py`。

## 下書きの形

- 種類 A の事実(数字・日付・曜日・時刻・山の名前・危険信号・天気)を含む文の終わりに、根拠の印 `[Y003]` などを付ける(1 文にいくつでも)。
- 決まった文は資料の文を一字一句そのまま写し、印 `[L1]` などを付ける。写した部分は、ほかの検査(数字・英語など)から外して照らす。
- 比べる文(いちばん・最も)には、比べた結果の印 `[C1]` などを付ける(下の「比べる文」)。
- 危険信号の件数を書く文には、件数の印 `[N1]` などを付ける(下の「危険信号の件数」)。
- 星の地点と夜を書く文には `[S001]` など、星の件数・夜の状態を書く文には `[T1]` などを付ける(下の「星の答え」)。夜に見られる星や惑星(見どころ)には `[H1]`、流星群には `[M1]`(ホシビヨリの新しい出力のときだけ)。
- 最後の行に `[おすすめ] Y003, Y005`(すすめた事実の id。なければ `[おすすめ] なし`)。送る文からは取り除く。
- 照らす前に、文字の形をそろえる(全角の数字・括弧を半角に、`°C` を `℃` に、`2,899` を `2899` に)。
- 文は「。!?」と改行で分ける。行の頭の印は前の文のもの。行の頭の `- `・`1. `・`**` は文の中身から外す。

## 印のある文

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `unknown_mark` | 資料にない印 | 資料にある事実の印だけを付ける |
| `number_mismatch` | 数(単位つき・点数・距離・標高・時刻の「時」)が、印の事実の「書いてよい表記」にない(「約」の有無も含めて一致を見る。単位のない数は値だけを見る。「3つ」など数え方の語のついた数は見ない) | 事実の書いてよい表記をそのまま使う(自分で丸めない) |
| `date_mismatch` | 日付(`11月17日`・`11/17`・`2026-11-17`)・曜日(`土曜`・`(土)`・`土日`)が印の事実の日と合わない。印が決まった文・足りないものだけのときは、対象の日と照らす。比べた結果の印 `[C…]`・件数の印 `[N…]` は、その日と照らす | 印の事実の日付・曜日を書く |
| `time_mismatch` | 時刻(`7:32`)が資料にない | 資料にある時刻だけを書く |
| `mountain_unmarked` | 資料にある山を書いたが、その山の事実の印がない(2 つ以上の山を 1 文で比べるときは、それぞれの印が要る) | その山の事実の印も付ける |
| `mountain_not_in_brief` | 資料にない山(76 座のうちの、資料に入っていない山)。質問に書かれた山は名前を出してよい | 資料にある山だけを書く |
| `hazard_mismatch` | 危険信号の語(雷・強風・低体温症・危険信号 + 注意・警戒・危険)が、印の事実の危険信号と合わない。種類(雷・強風・低体温症)を書かずに段階だけを言う文は、印の事実の**いちばん重い段階**と照らす(下の「段階だけを言う文」) | 印の事実の危険信号の語を書く |
| `url_not_in_brief` | URL | URL を書かない |

### 段階だけを言う文(利用者の決定 2026-11-23)

種類を書かずに「危険信号が警戒まで出ています」のように言う文。通る言い方の形は `words.hazard_level_forms`(仮置き):

| 言い方 | 合っているとみなすとき |
|---|---|
| 「危険信号が警戒まで」「警戒までの危険信号」 | いちばん重い段階がちょうど警戒(70 点未満の山の「警戒以上」は、上の段階が分からないので合わないとみなす) |
| 「危険信号が警戒以上」「警戒以上の危険信号」 | いちばん重い段階が警戒か危険 |
| 「危険信号が警戒」「警戒の危険信号」「危険の危険信号」 | いちばん重い段階がちょうどその段階 |
| 上のどれかのすぐあとに「出ていません」「ありません」など(`words.hazard_level_not_re`。仮置き) | その段階の危険信号が出ていない |

印の事実が 2 つ以上あるときは、節(「、」まで)に書かれた山・日の事実で照らす。節に山がなければ文の中の山、それもなければ印の事実の全部で、**1 つでも合わなければ止める**。
「警戒の危険信号」のように段階を先に書く形は、これまで照らしていなかった(今は照らす)。「強風警戒の危険信号」のように種類を書いた形は、今までどおり種類と段階の組で照らす。

## 印のない文

| コード | 何を止めるか | 語の一覧の場所 |
|---|---|---|
| `number_unmarked` | 数字と単位(単位の一覧の語が続く数)。点数もここ | `numbers.units` |
| `date_unmarked` | 日付。曜日は対象の日の曜日だけ通す(「今日」「明日」「今週末」「来週末」は数字を含まないので通る) | — |
| `time_unmarked` | 時刻(`7:32`) | — |
| `url_unmarked` | URL | — |
| `weather_unmarked` | 天気の語(晴・雲・風・雨・雪・霧・雷・見通し・気温・寒 など)。**山の名前の有無にかかわらず**止める。山の名前(霧ヶ峰・雲取山など)は先に取り除いてから照らす。「風景」「素晴らしい」など天気の話でない語と、種類 C の語(積雪・雪山など)は先に取り除く | `words.weather`・`words.weather_ok` |
| `hazard_unmarked` | 危険信号の語(強風・低体温症・危険信号) | `words.hazard_kinds` |
| `mountain_not_in_brief` | 資料にない山の名前(質問に書かれた山は通す) | — |

山の名前と一般的な知識だけの文(名前の由来、景色で知られること、など。種類 B)は通す。

## 印があってもなくても

| コード | 何を止めるか | 語の一覧の場所 |
|---|---|---|
| `unknown_mountain` | 76 座にない山の名前らしい語(「…山」「…岳」「…峰」「…嶺」で終わる語)。登山・低山・雪山などのふつうの語と、質問に書かれた語は通す。**形で見るだけなので、この形でない山の名前は止められない(仮置き)** | `words.mountain_re`・`words.mountain_common` |
| `safety_without_basis` | 山の安全に関わる語(種類 C: 装備・凍結・積雪・残雪・難易度・初心者・上級者・所要時間・コースタイム・通行止め・引き返す・「登れます」・安全・岩場・急坂 など)に裏づけがない。通すのは、(1) 知識カードの印 `[K…]`、(2) 危険信号のある事実の印(ただし語が `words.safety_hazard_ok` の防寒・雨具・引き返す・装備だけのとき。難しさ・岩場・急坂・凍結・積雪・所要時間などは通さない。作業指示書 6.2 より厳しくした点)、(3)「判断できません」「判断できないので」「判断できず」「この資料にはありません」「分かりません」などの形の文(`words.safety_exempt`。「判断できないわけではない」のように打ち消す形は通さない)。**足りないものの印 `[G…]` だけでは通さない**(段階 2 の仕上げ 6.1。`[G…]` の文も (3) の形で書く) | `words.safety`・`words.safety_hazard_ok`・`words.safety_exempt` |
| `safety_assertion` | 安全の言い切り(安全・登れます・大丈夫・初心者でも など)に、知識カードの印がない(印のある文だけ見る。印のない文は `safety_without_basis`)。危険信号の事実の印では通さない(段階 2 の通しの試しで「…は100点なので登れます。[危険信号つきの事実]」が通ったため足した。作業指示書 6.2 より厳しくした点) | `words.safety_positive` |
| `pick_undeclared` | おすすめの語(おすすめ・ベスト・行くなら など)のある文で、印の山がどれも `[おすすめ]` にない。「見送」を含む文は見ない(「行くならと考えた○○は見送る」を止めないため。通しの試しで止めすぎた)。「点数がいちばん高い」が本当かは、下の「比べる文」で見る | `words.recommend`・`words.recommend_not` |
| `score_across_biyori` | 点数の語と、ほかのビヨリの語(星・紅葉・花・生き物 など)が同じ文にある(段階 2 では起きないが、検査は作った) | `words.other_biyori` |
| `lodging_name` | 宿・山小屋の具体名らしい語(「…山荘」「…小屋」「…ヒュッテ」「…ホテル」「…荘」など。「山小屋」「避難小屋」は通す)。**名前の一覧は持っていないので、この形でない名前(「○○館」など)は止められない(仮置き)** | `words.lodging_re`・`words.lodging_ok` |

## 古い予報のとき(利用者の決定 2026-11-25)

資料の `shelf.stale` が真(予報の時点から `config.yaml` の `collect.stale_after_hours` 時間以上。24 時間)のときだけ見る。

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `stale_first` | 答えの最初の文が、予報の時点(古さ)の決まった文 `data_time` でない | `data_time` の文を最初に置く |
| `stale_assertion` | 「おすすめ」「イチオシ」「最適」「ベスト」など言い切りの語がある。「行くなら」は「候補」と一緒なら書いてよい。「おすすめの候補の中で」は書いてよい | 「古い予報では、○○が候補です」と書く |
| `stale_refresh_last` | 新しくする方法の文 `refresh` のあとに、ほかの文がある(あとに書けるのは帰属の文だけ) | `refresh` を最後に置く |
| `line_missing` | 決まった文 `refresh` がない | 答えの最後にそのまま写す |

Stop フックも、資料が古い回で「おすすめ」と言い切った文なら止める(`concierge/stop_hook.py` の `stale`)。

## 生の雲量が 0 % の山(利用者の決定 2026-11-25)

資料の `facts[].cloud_clear` が真の山(雲の印。生の雲量がちょうど 0 %)は、補正後の数字を書かず「雲はほとんど無い予報です」のように書く。
節(「、」まで)ごとに、どの山のどの日のことかを決めて見る(節に山の名前が無ければ、文の中の前の節の山。それも無ければ、文の印の山の全部)。語の形は `cloud`(仮置き)。

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `cloud_number` | 印の付いた山に、雲量の数字(%・割)を書いている(補正後の値も、生の 0 % も)。1 つの節に印のある山と無い山を並べた数字も、印の無い山の雲量の値でなければ止める | 言葉で書く。比べるときは、数字を書く山の名前を同じ節に書く |
| `cloud_assertion` | 印の付いた山に「快晴」「雲ひとつない」「雲がまったくない」などと言い切っている | 「雲はほとんど無い予報です」 |
| `cloud_mismatch` | 印の無い山に「雲はほとんど無い」と書いている(「どちらも雲はほとんど無い」は、両方に印があるときだけ) | 印の無い山は、雲量の数字を「書いてよい表記」で書く |

「雲はほとんど無い」の「ほとんど」は、危険信号の割合の語(`hazard_vague`)・風の差の語(`gap_unmarked`)と読み違えないよう、その 2 つの検査では先に取り除く。
Stop フックも、`cloud_number`・`cloud_assertion` に当たる文なら止める(`concierge/stop_hook.py` の `cloud`。山の名前から、どの山のことか決められない文は通す)。

## 山を名指しした質問(利用者の決定 2026-11-25)

`brief` に `--mountain` を渡した質問だけで見る(棚が使えない回は見ない)。判定は `concierge/named.py`(控えの文・`verify`・Stop フックが同じものを使う)。語の形は `named`(仮置き)。

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `named_missing` | 名指しの山が答えに出ていない(山ごとに 1 回は要る。日ごとではない)。予報の無い名指しの山(76 座に無い・250km より遠い・その日の予報が無い)も、名前が要る | 名指しの山を 1 座ずつ書く。予報の無い山は、足りないもの `[G…]` の文で最初に伝える |
| `named_other` | 名指しでない山の名前がある。決まった文(見送りのまとめ・名指しでない山の危険信号の文)の中の名前も見る。質問の文に書かれた山は通す | その山を消す |

- 例外は 1 文だけ: 予報のある名指しの山の全部に危険信号が出ている日に、その日の危険信号の無い、主役にできる山 1 座について「なお、この日は○○には危険信号が出ていません。」(名指しの山の話のあと。点数・風などを書き足さない。資料と合わなければ止める)。
- すすめる山の決め方(控えの文と、資料の決まり): 主役にできる名指しの山のうち、点数がいちばん高く、危険信号の段階がいちばん軽い山。同じなら「差がつきません」(距離・ID・危険信号の数・風では決めない)。AI の書いた文が、この決め方のとおりかまでは照らさない(すすめた山が主役にできるかは今までどおり照らす)。
- 最初の文の形・「予報の無い山を最初に」・「くわしい値はありません」は、資料の決まりと控えの文で守る(`verify` は順番までは見ない)。古い予報では、`data_time` → 予報の無い山 → 結論の順(`stale_first` は変えていない)。
- 資料の名指しの文字列(76 座に無い山)は、質問の文に無くても名前を出してよい(`unknown_mountain` で止めない)。

Stop フックも同じ判定で止める(`concierge/stop_hook.py` の `named`)。その文を `verify` が出した資料だけで見る(1 回に資料が 2 つあるとき、もう一方の決まりを当てない)。

## 比べる文

最上級の語(いちばん・一番・最も・もっとも・最高・最低 など。`compare.superlatives`)と、比べる対象の語(風・近い・遠い・高い・低い・点数・少ない・寒い など。`compare.topics`)が同じ文にあるときに見る。
山の名前(高尾山 など)は先に取り除く。「いちばんのおすすめ」「最高峰」など(`compare.ok`)は比べる文とみなさない。
比べる対象は、最上級の語のあとの語(いちばん「弱い」)→ 同じ節(「、」まで)の語 → 文の中の語、の順に決める。語の一覧はどれも仮置き。

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `comparison_unmarked` | 比べた結果の事実の印 `[C…]` がない(対象の違う `[C…]` も同じ)。資料が作る比べた結果は「稜線の風がいちばん弱い」「出発地からいちばん近い」だけなので、ほかの比べ方(いちばん遠い・標高がいちばん低い・雲量がいちばん少ない など)はいつも止まる | 資料の「比べた結果」にあるものだけを書く。ほかは数字だけを書く |
| `comparison_mismatch` | 印の事実の山・日と、文の山・日が合わない。1 つの節に 2 つ以上の山がある。「点数がいちばん高い」に、その日の順位(`rank`)が 1 位の事実の印がない | 1 つの文に 1 つの山だけを書き、その山の `[Y…]` と `[C…]` を付ける |
| `comparison_tied` | 同点の山があるのに、1 つの山だけを「点数がいちばん高い」と書いた | 順位の表記(「1位(同点 5 座)」)で書く |
| `comparison_scope` | `[C…]` を使う文に「候補」の語がない(比べたのは主役の枠の山の中だけ) | 「おすすめの候補の中で」と書く |
| `gap_unmarked` | 風の差が「わずか」などと言っているのに、名指しの山どうしの差の印 `[C…]`(`peak_wind_gap`)がない | 資料の「名指しの山どうしの差」の印を付ける |
| `gap_mismatch` | わずかでない差を「わずか」と書いた | 差の数字だけを書く |
| `number_lone` | 山を 2 つ以上名指しした答えで、番号が 1 行だけに付いている | 番号を全部に付けるか、全部から外す |
| `rank_tie_hidden` | 同点のある順位を「1位」とだけ書いた | 「1位(同点 5 座)」と書く |

見送りを言う文(「見送」を含む文)にも、風・距離・点数の検査を当てる(点数は利用者の決定 2026-11-23。`compare.score_skip` は空)。

## 危険信号の件数と「どれも・全部」

資料に載る山は枠の中だけなので、その日の山の全部のことは、件数の事実 `[N1]`〜(`hazard_counts`。日ごとに、基準点以上の山のうち危険信号が警戒・危険の山の数。山のいちばん重い段階で数える)でしか言えない。
語の一覧はどれも仮置き(`hazard_count`)。**合うかどうかを機械的に決められない言い方は止める。**

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `hazard_universal_unmarked` | 「どれも」「全部」「すべて」「どの山も」など(`hazard_count.universal`)と危険信号の語(危険信号・強風・低体温症・雷・警戒・危険)が同じ文にあるのに、件数の印 `[N…]` がない(山の名前を並べた「どれも」は下) | 「どれも」をやめて、件数を書く |
| `hazard_universal_mismatch` | 「どれも…」の範囲・段階・日が件数と合わない、または決められない。通すのは、「基準」(`universal_scope`)と書いた基準点以上の山の全部について、「危険信号が出ている」「警戒以上」「警戒」「危険」だけを言う文(と、警戒以上などが「出ていない」と言う文)で、件数が合うときだけ。種類(強風など)・「注意」・「まで」などを言う文は決められないので止める。日を書かない文は、対象の日の全部の印が要る | 日を書き、件数の「書いてよい言い方」で件数を書く |
| `hazard_count_unmarked` | 危険信号の語のある文に山の数(○ 座・○ 件)を書いたのに、件数の印がない(順位の「同点 ○ 座」は見ない) | その日の `[N…]` を付ける |
| `hazard_count_mismatch` | 山の数が、すぐ前の段階の語(警戒以上・警戒・危険・基準)の件数と合わない、または何の数か決められない。日が合わない・1 文に 2 つの日の件数。件数の印だけの文に種類(強風など)を書いた | 1 つの文に 1 つの日だけを、「書いてよい言い方」で書く |
| `hazard_vague` | 危険信号の語と同じ文にある、割合・ぼかした言い方(ほとんど・大半・半分以上・多くの山・ほかの山も・高い山ほど など。`hazard_count.vague`。仮置き)。本当かどうかは照らさずに止める(件数の印があっても止める) | 件数の文を写す(例: 危険信号が警戒以上の山は 31 座) |

- `say`(書いてよい言い方)に入れるのは全体の件数だけ。枠の外の件数は資料の Markdown に出すが、書き手が見るだけ(答えに挙げた山の数は枠の数と同じとは限らないため)。
- 「どちらも」「多い」は見ない。「ここに挙げた 3 つの山は」のように数え方の語「つ」を使う文も見ない(印の事実の危険信号とは照らす)。
- **山の名前を並べた「どれも」**(「A・B・C は、どれも強風危険です」。利用者の決定 2026-11-24): 並べた山の全部に事実の印があり(日を書いていれば、書いた日ごとに)、
  **どの印の事実も**、文の危険信号(種類と段階)を持っているときは、件数の印がなくても通す。1 つでも合わなければ、今までどおり止める。
  通すのは、名前を「・」「、」「と」でつないだすぐあとに「どれも」などが続く形だけ(`hazard_count.listed_sep`・`listed_tail`)。文に件数の印 `[N…]`・「基準」などの語(`listed_not`)があるとき、
  危険信号を言う節に打ち消しがあるとき(`listed_not_clause`)は、今までどおり件数と照らす。
- 止めすぎと分かっているもの: 並べた名前と「どれも」のあいだに別の話が入る文(「A・B は点数が高いですが、どれも強風危険」)、「A・B・C の 3 座は、どれも」(3 座が件数の印を求める。「3 つ」なら通る)、
  日の違う山を並べる文(「土曜の A と日曜の B は、どれも」)、名前を並べた「どれも…出ていません」、「主役の候補はどれも危険信号が出ていません」(件数は警戒以上しか数えていない)。

## 星の答え(段階 3。資料に星の部分があるときだけ。コードは `concierge/stars_verify.py`)

星の地点の名前は、照らす前に置き換える(「石割山(山中湖村)」の中の山の名前・天気の語を読まない)。語の一覧は `verify.yaml` の `stars`(仮置き)。

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `night_label` | `[S…]`・`[T…]` を付けた文に「28日(土)の夜」の表記がない。星・夜の文の「28日から29日」「28〜29日」「28日深夜」「29日未明」「土曜の深夜」など | 「11月28日(土)の夜」か「28日(土)の夜」と書く |
| `night_time` | 0 時を過ぎた時刻に「翌」がない・余分にある | 「翌2:30」の形にする |

| `site_label` | 市町村を付けない地点の名前(同じ名前の地点があるため) | 「書いてよい表記」の形で書く |
| `unknown_site` | 一覧にない場所の名前らしい語(○○高原・○○湖・○○展望台 など) | 資料にある地点だけを書く |

- Stop フックは変えていない(`mismatch` で `verify` の文と比べる)。名指しの検査と雲の検査は、地点の名前を取り除いてから読む。

## 危険信号の注記の置き直し(照らすのではなく、送る文を作るときに直す)

合格した下書きから送る文を作るとき、`verify` は注記の決まった文(`lines.hazard_note`)を 1 つだけ、正しい位置に置き直す(`place_note`。利用者の決定 2026-11-24)。ほかの文の順番・中身は変えない。

- 位置: **最後の危険信号の決まった文(山ごと `hazards`・見送りのまとめ `skips`)・件数の文(`[N…]` のある文)のあと。そのあとに足りないものの文があれば、その前。** 前後を空行で分けて、1 つの段落にする。
  足りないものの文とみなすのは、`[G…]` の印のある文と、印がなくて「判断できません」などの形(`words.safety_exempt`)の文。行の途中にあれば、そこで段落を分ける。
  あとに足りないものの文がなければ、最後の危険信号の文・件数の文のある段落の終わり(出典の文 `attribution` があれば、その前)。
- 下書きに 2 回以上あれば 1 回にする。危険信号の決まった文(`hazards`・`skips`)があるのに注記がなければ足す(前の検査 `hazard_note_missing` はやめた)。
- 危険信号の決まった文が 1 つもなければ、注記を出さない(件数の文だけのとき・自分の文で危険信号を書いただけのときも)。
- 注記の文を書き換えて印 `[L…]` を付けたときは、今までどおり `line_altered`。字数(`too_long`)は、置き直したあとの文で数える。
- `last_answer.json` に残るのも、置き直したあとの文。

## 分かっている限界

- **印のある文の天気の語の中身は照らさない。** 「一日中晴れる見込みです。[Y004]」は、雲量が何 % でも通る。空の様子を言葉にする基準(何 % から晴れか)はヤマビヨリの出力に無いので、コンシェルで決めない(例外は、生の雲量が 0 % の山の「雲はほとんど無い」と「快晴」など。上の「生の雲量が 0 % の山」)。
- 比べる文で照らすのは、上の最上級の語と対象の語の組だけ。「より弱い」「日曜のほうが高い」のような 2 つを比べる文の中身は照らさない。
- 比べた結果 `[C…]` は、主役の枠の山だけを比べる。名指しで枠の外にある主役にできる山は比べていないので、その山のほうが近い・風が弱いことがある(6.2 のとおり)。
- 「候補の中で」がどの日の候補かは、文の山の印 `[Y…]` の日と `[C…]` の日が合うことまでしか見ない(日を書かない文は止めない)。
- 「判断できません」「判断できないので」「分かりません」の形を含む文は、その文のほかの部分に種類 C の語があっても `safety_without_basis` では止めない(「難しさは分かりませんが、凍結しています」)。
- 「どれも」「全部」「どの山も」の文は、危険信号の語が同じ文にあるときだけ照らす。危険信号以外のこと(「どの山も雲量が少ない」など)や、一覧にない言い方の中身は照らさない。「ほとんど」「ほかの山も」なども、危険信号の語が同じ文にあるときだけ止める。
  数字は算用数字だけを照らす(「六座」は見ない)。件数の範囲は「基準」の語があるかまでしか見ない(「関東の山の全部」のような地域の言い方は照らさない)。
- 「危険信号は出ていません」(段階を書かない打ち消し)が事実と合うかは、名指しの例外の 1 文のほかでは照らさない。
- 「点数の高い山が多い」「寒さが軽い」のような、数えた結果・程度の言い方の中身は照らさない。
- 76 座にない山・宿の名前は、語の終わりの形でしか見つけられない。

## 控えの文

照合に 3 回通らなかったときに、資料だけから作る文(`concierge/fallback.py`)。印つきの下書きとして組み立て、同じ検査に通してから出す(テストで、見本のいくつもの形で通ることを確かめている)。
並びは「結論 → `data_time`・`coverage` → おすすめ 3 つまで(日ごとの上位。主役にできる山だけ)と事実・危険信号の文 → 先の予報の文 → 見送り(名指しの山と、見送りの枠のまとめの文 2 日ぶんまで。日の順は、枠の先頭の山が見送りの枠の並びで先の日から = 危険の段階の重い順。まとめの文に件数の文を続ける)→ 危険信号の注記(1 回。足りないものの文の前)→ 足りないもの → `attribution`」。
山を名指しした質問では、並びは「結論(名指しの山の中から)→ `data_time`・`coverage` → 名指しの山を 1 座ずつ → 違い → 先の予報の文 → 例外の 1 文 → 危険信号の注記 → 足りないもの → `attribution`」。予報の無い名指しの山があれば、その文を結論の前に置く。
名指しが 4 座以上でも全部書く。違いの文は、3 座以上なら日中ピークの風速の差がいちばん大きい組だけ。日が多いときは、山と日の組を 6 つまで(仮置き。`MAX_NAMED_BLOCKS`。どの山も 1 回は書く)にして、ほかの日は省いたと書く。

## 記録

置き場の `logs/answers.jsonl` に 1 行: 資料の id・時刻・結果(合格・不合格・控え)・書き直しの回数・落ちた検査のコード名。答えの本文は入れない。
回数は置き場の `briefs/<id>.verify.json` で数える。同じ資料を `brief` で作り直すと数え直す。
