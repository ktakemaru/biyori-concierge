# 照合(`concierge verify`)の検査の一覧

`verify <下書き> --brief <id>` が下書きを資料と照らす。1 つでも当たれば不合格(終了コード 1。標準エラーに文ごとの理由と直し方)。
書き直しは 2 回まで(`config.yaml` の `answer.max_rewrites`)。3 回目も不合格なら、資料から作った控えの文を出す(終了コード 0)。
語の一覧と値は `concierge/data/verify.yaml`(**どれも仮置き**)。コードは `concierge/verify.py`。

## 下書きの形

- 種類 A の事実(数字・日付・曜日・時刻・山の名前・危険信号・天気)を含む文の終わりに、根拠の印 `[Y003]` などを付ける(1 文にいくつでも)。
- 決まった文は資料の文を一字一句そのまま写し、印 `[L1]` などを付ける。写した部分は、ほかの検査(数字・英語など)から外して照らす。
- 最後の行に `[おすすめ] Y003, Y005`(すすめた事実の id。なければ `[おすすめ] なし`)。送る文からは取り除く。
- 照らす前に、文字の形をそろえる(全角の数字・括弧を半角に、`°C` を `℃` に、`2,899` を `2899` に)。
- 文は「。!?」と改行で分ける。行の頭の印は前の文のもの。行の頭の `- `・`1. `・`**` は文の中身から外す。

## 印のある文

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `unknown_mark` | 資料にない印 | 資料にある事実の印だけを付ける |
| `number_mismatch` | 数(単位つき・点数・距離・標高・時刻の「時」)が、印の事実の「書いてよい表記」にない(「約」の有無も含めて一致を見る。単位のない数は値だけを見る。「3つ」など数え方の語のついた数は見ない) | 事実の書いてよい表記をそのまま使う(自分で丸めない) |
| `date_mismatch` | 日付(`11月17日`・`11/17`・`2026-11-17`)・曜日(`土曜`・`(土)`・`土日`)が印の事実の日と合わない。印が決まった文・足りないものだけのときは、対象の日と照らす | 印の事実の日付・曜日を書く |
| `time_mismatch` | 時刻(`7:32`)が資料にない | 資料にある時刻だけを書く |
| `mountain_unmarked` | 資料にある山を書いたが、その山の事実の印がない(2 つ以上の山を 1 文で比べるときは、それぞれの印が要る) | その山の事実の印も付ける |
| `mountain_not_in_brief` | 資料にない山(76 座のうちの、資料に入っていない山)。質問に書かれた山は名前を出してよい | 資料にある山だけを書く |
| `hazard_mismatch` | 危険信号の語(雷・強風・低体温症・危険信号 + 注意・警戒・危険)が、印の事実の危険信号と合わない | 印の事実の危険信号の語を書く |
| `url_not_in_brief` | URL | URL を書かない |

## 印のない文

| コード | 何を止めるか | 語の一覧の場所 |
|---|---|---|
| `number_unmarked` | 数字と単位(単位の一覧の語が続く数)。点数もここ | `numbers.units` |
| `date_unmarked` | 日付。曜日は対象の日の曜日だけ通す(「今日」「明日」「今週末」「来週末」は数字を含まないので通る) | — |
| `time_unmarked` | 時刻(`7:32`) | — |
| `url_unmarked` | URL | — |
| `weather_unmarked` | 天気の語(晴・雲・風・雨・雪・霧・雷・見通し・気温・寒 など)。**山の名前の有無にかかわらず**止める。山の名前(霧ヶ峰・雲取山など)は先に取り除いてから照らす。「風景」「素晴らしい」など天気の話でない語と、種類 C の語(積雪・雪山など)は先に取り除く | `words.weather`・`words.weather_ok` |
| `hazard_unmarked` | 危険信号の語(強風・低体温症・危険信号) | `words.hazard_kinds` |
| `mountain_not_in_brief` | 資料にない山の名前(質問に書かれた山は通す) | — |

山の名前と一般的な知識だけの文(名前の由来、景色で知られること、など。種類 B)は通す。

## 印があってもなくても

| コード | 何を止めるか | 語の一覧の場所 |
|---|---|---|
| `unknown_mountain` | 76 座にない山の名前らしい語(「…山」「…岳」「…峰」「…嶺」で終わる語)。登山・低山・雪山などのふつうの語と、質問に書かれた語は通す。**形で見るだけなので、この形でない山の名前は止められない(仮置き)** | `words.mountain_re`・`words.mountain_common` |
| `safety_without_basis` | 山の安全に関わる語(種類 C: 装備・凍結・積雪・残雪・難易度・初心者・上級者・所要時間・コースタイム・通行止め・引き返す・「登れます」・安全・岩場・急坂 など)に裏づけがない。通すのは、(1) 足りないものの印 `[G…]`、(2) 知識カードの印 `[K…]`、(3) 危険信号のある事実の印(ただし語が `words.safety_hazard_ok` の防寒・雨具・引き返す・装備だけのとき。難しさ・岩場・急坂・凍結・積雪・所要時間などは通さない。作業指示書 6.2 より厳しくした点)、(4)「判断できません」「この資料にはありません」「分かりません」などの形の文 | `words.safety`・`words.safety_hazard_ok`・`words.safety_exempt` |
| `safety_assertion` | 安全の言い切り(安全・登れます・大丈夫・初心者でも など)に、知識カードの印がない。危険信号の事実・足りないものの印では通さない(段階 2 の通しの試しで「…は100点なので登れます。[危険信号つきの事実]」が通ったため足した。作業指示書 6.2 より厳しくした点) | `words.safety_positive` |
| `pick_undeclared` | おすすめの語(おすすめ・ベスト・行くなら など)のある文で、印の山がどれも `[おすすめ]` にない。「見送」を含む文は見ない(「点数がいちばん高い○○は見送る」を止めないため。通しの試しで止めすぎた) | `words.recommend`・`words.recommend_not` |
| `score_across_biyori` | 点数の語と、ほかのビヨリの語(星・紅葉・花・生き物 など)が同じ文にある(段階 2 では起きないが、検査は作った) | `words.other_biyori` |
| `lodging_name` | 宿・山小屋の具体名らしい語(「…山荘」「…小屋」「…ヒュッテ」「…ホテル」「…荘」など。「山小屋」「避難小屋」は通す)。**名前の一覧は持っていないので、この形でない名前(「○○館」など)は止められない(仮置き)** | `words.lodging_re`・`words.lodging_ok` |

## 全体

| コード | 何を止めるか | 直し方 |
|---|---|---|
| `line_missing` | 決まった文 `data_time`・`coverage`・`attribution` がない(資料にあるとき) | 資料の文をそのまま写す |
| `line_altered` | 決まった文の印 `[L…]` があるのに、文が書き換えてある | 一字一句そのまま写す |
| `picks_missing` | 最後の行の `[おすすめ]` がない | `[おすすめ] Y…` か `[おすすめ] なし` を書く |
| `pick_unknown` | `[おすすめ]` の id が山の事実にない | 山の事実の id を書く |
| `pick_not_allowed` | 主役にできない山(基準点未満・危険信号が警戒以上・点数だけ)をすすめた | 見送りとして書く |
| `pick_not_in_plans` | すすめた山が資料の組み合わせ(`plans`)の主役にない | 組み合わせの主役だけをすすめる |
| `hazard_line_missing` | すすめた山に危険信号があるのに、その `lines.hazards` の文がない | その文をそのまま写す |
| `lead_time_missing` | すすめた山の日が信用してよい範囲(3 日先まで)の外なのに、`lines.lead_time` の文がない | その文をそのまま写す |
| `internal_word` | 内部の言葉・作業の経過(棚・manifest・proposal・band・資料・印・id・カード・照合・検査・下書き・合格・コード など)。決まった文と「この資料からは判断できません」などの形は外して照らす | 利用者の言葉に言い換える(`words.internal`) |
| `english_note` | 英語の語が 3 つ以上続く(決まった文の中の「Weather data by Open-Meteo.com」は外して照らす) | 英語のメモを書かない(`words.english_re`) |
| `question_in_answer` | 読む人への問いかけ(「?」「〜ますか」「〜でしょうか」「いかが」「〜ませんか」) | 質問をしない(`words.question`) |
| `offer_in_answer` | できないことの提案(「〜しましょうか」など) | 提案しない(`words.offer`) |
| `too_long` | 送る文が `config.yaml` の `answer.max_chars`(2,000 字。仮置き)を超える | 短くする |

## 控えの文

照合に 3 回通らなかったときに、資料だけから作る文(`concierge/fallback.py`)。印つきの下書きとして組み立て、同じ検査に通してから出す(テストで、見本のいくつもの形で通ることを確かめている)。
並びは「結論 → `data_time`・`coverage` → おすすめ 3 つまで(日ごとの上位。主役にできる山だけ)と事実・危険信号の文 → 先の予報の文 → 見送り(名指しの山・危険信号で外した山 2 つまで)→ 足りないもの → `attribution`」。

## 記録

置き場の `logs/answers.jsonl` に 1 行: 資料の id・時刻・結果(合格・不合格・控え)・書き直しの回数・落ちた検査のコード名。答えの本文は入れない。
回数は置き場の `briefs/<id>.verify.json` で数える。同じ資料を `brief` で作り直すと数え直す。
