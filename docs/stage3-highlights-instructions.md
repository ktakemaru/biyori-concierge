## 6. 第 3 部: 夜に見られる星(`highlights`)

ホシビヨリの報告書の条件 1〜5 のとおりにする。

1. **星の見どころの事実**を資料に足す。1 件は「夜と対象」(流星群は別の種類)。印の字は、今ある字(山・山の件数・比べた結果・星の地点と夜・星の件数)と**別の字**にする。
   - 作る条件: 出力に `highlights` があり、その夜の `by_night[night_date]` が `null` でない。
   - 持つもの: 夜の日付と書いてよい表記(「○日(土)の夜」)・時間帯(宵・夜半・明け方)・書いてよい名前(`members[]` の名前)・見える時刻・最大高度とその時刻(あれば)・`basis.text`・`coordinates_unverified`。
   - `not_visible` の対象は「今の時期は見えない」と書ける事実にする。**`slots` に無い対象を「見えない」と書かせない**(上限 4 件・30 分より短い対象は入らないため)。
   - 流星群: 極大の日・放射点の高い時間帯・`zhr_note`・`caveat`。
2. **一日の流れの案の「夜」の枠**に、その夜の見どころの事実を結ぶ。星の地点が付かない日(近くに地点が無い・条件を通らない)でも、見どころは地点によらない目安なので、**星の地点が付いた日にだけ**夜の枠に入れる(地点が無いのに星の名前だけ書かない。仮置き)。星が起点の案も同じ。
3. **答えの決まり**:
   - 書いてよいのは、事実にある名前と時刻だけ。夜中の 0 時を過ぎた時刻は今までどおり「翌」を付ける。
   - **`basis.text`(基準の地点・平らな地平線の目安。地形・雲は見ていない)を、見どころを書いた答えに必ず 1 回入れる**(決まった文として資料が用意する)。
   - `coordinates_unverified: true` の対象は、**今回は答えに書かせない**(安全側。件数を報告書に書き、「目安と分かる書き方で書く」案を決めてほしいことに入れる)。
   - 流星群を書くときは `zhr_note` と `caveat` の文を必ず添える(資料が決まった文として用意する)。出現数の数字を、添える文なしで書いた答えは止める。
   - 月が出ている時間帯・雲の予報と、見どころを混ぜない(「晴れていれば」「月の無い時間帯は」の言い方は、星の地点と夜の事実にある値だけで書く)。
4. **「どの星や惑星が見えるかは、この予報に含まれていません」**(`no_star_objects`)は、見どころの事実が無いとき(古い版の出力・その夜が `null`)だけ出す。
5. **照合(`verify`)**: 今の `star_object` の決まり(星の名前を書いたら止める)を、「見どころの事実にある名前は、その事実の印と同じ文にあれば通す。事実に無い星・星座・惑星・流星群の名前は止める」に直す。時刻・夜の表記・`basis` の文・流星群の添える文も照らす。`docs/answer-checks.md` を合わせる。
6. 控えの文(`fallback`)・`docs/answer-voice.md`(手本を足す: 山と星と見どころがそろった日・見どころが無い夜・流星群の夜(実物にあれば))・`docs/brief-fields.md`・`SKILL.md`・`AGENTS.md` を合わせる。字数の上限 2,000 字は変えない。超えるときは、見どころを 1 つの時間帯あたり 2 つまでに絞る(仮置き。絞り方はコードが決め、ホシビヨリの並びの上から)。
