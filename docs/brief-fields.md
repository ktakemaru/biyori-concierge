# 資料(`biyori-brief/1`)に出す予報の値と決まった文の出典

`concierge brief` が、棚の提案(`proposals/yamabiyori.json`)の `evidence[]` から資料に出す値の一覧。
名前と単位は、ヤマビヨリ(`C:/yamabiyori`、commit `fdadece`・1.10.1)の README と画面の列名に合わせた。**名前の出典が見つからない値は出さない。**
コードの対応表は `concierge/brief.py` の `VALUE_FIELDS`。

## 出す値

| 値(`metric`) | 答えに出る名前(資料での名前) | 単位 | 「約」の表記 | 出典の場所 |
|---|---|---|---|---|
| `score`(提案の `suitability.score.value`) | 点数(基準 70 点) | 点 | 1 点の刻み | README「行ける」の目安 70点以上・`mountain_weather_mvp.py` 表の列「スコア」 |
| `ridge_wind_ms` | 稜線風速 | m/s | 1 m/s の刻み | `mountain_weather_mvp.py` `print_ranking_table()` の列「稜線風速m/s」・README 探索モードの表「稜線風速」 |
| `day_peak_wind_ms`(+ `day_peak_wind_hour`) | 日中ピークの風速(と、その時刻「6時」) | m/s | 1 m/s の刻み | README「スコアの仕組み」の危険信号「稜線の強風(日中ピーク)」・`hazard_warning_cell()` の「強風…(06時16.4m/s)」 |
| `cloud_pct` | 雲量 | % | 1 % の刻み | README 探索モード「雲量%(較正/生)は左が採点に使う較正後の実効雲量」。**値はヤマビヨリが採点に使う実効雲量(予報の雲量を過去の的中率で直した較正後の値)**。README「スコア」の表は「雲量 … 実効雲量」と「雲量」の名前で書いている。答えには「較正」と書かない(資料の Markdown の注にだけある) |
| `ridge_visibility` | 視程(稜線) | m | 「約○ km」(1 km の刻み) | `print_ranking_table()` の列「視程m(稜線)」 |
| `precip_wet_pct` | 雨天割合(活動時間) | % | 1 % の刻み | 同「雨天割合%(活動時間)」・README「活動時間中の雨天割合」 |
| `day_total_precip_mm` | 降水量(全日) | mm | 1 mm の刻み | 同「降水量mm(全日)」 |
| `chill` | 体感温度(稜線) | ℃ | 1 ℃ の刻み | 同「体感温度℃(稜線)」 |

- 答えに出る名前は、ヤマビヨリの README・手順書・画面の列名にある言い方だけを使う。範囲の外になる言い換えはしない(候補は `docs/stage2-finish-report.md` 5 章)。
  「雨天割合(活動時間)」「視程(稜線)」は、ヤマビヨリ側で言い方を決めるまで今のまま(利用者の決定 2026-11-23)。
- **生の雲量(`cloud_pct_raw`)がちょうど 0 % の山**: 事実に印 `cloud_clear: true` を付け、`cloud_pct` の「書いてよい表記」を数字でなく「雲はほとんど無い予報」にする(利用者の決定 2026-11-25。
  補正で 0 % が 18.6 % などになり、空の 2 割が雲のように読めるため)。資料の Markdown にも数字を出さない(JSON の `values` の値は残る)。生の値そのものは資料に入れない。
  生の値が棚に無い山・0 % でない山は `false` で、今までどおり補正後の数字を書く。点数だけの山(簡易行)も `false`。
- 「約」の表記(丸め)は `brief` だけが作る(四捨五入。AI は丸めない)。丸めの刻みは仮置き。
- 70 点未満の山(簡易行)は `evidence` が空なので、点数と危険信号の段階(種類なし)だけを持つ。

## 答えに出さない値

名前と単位の出典はあるが、答えに出さないと決めた値。資料(JSON・Markdown・書いてよい表記)に入れないので、書くと照合が止める。
段階の語(「雷注意」など)は、危険信号として今までどおり出す。

| 値 | 名前・単位 | 出さない理由 | 決めたこと |
|---|---|---|---|
| `cloud_pct_raw` | 山頂雲量(予報そのまま)・% | 「雲量」(採点に使う実効雲量)と並ぶと、違いが読む人に分からない | 利用者の決定 2026-11-23 |
| `cape` | 雷リスク(CAPE)・J/kg | CAPE と J/kg が読む人に分からない。危険信号の文は「雷注意」「雷警戒」のように段階だけにする | 利用者の決定 2026-11-23 |

## 出していない値

| 値 | 理由 |
|---|---|
| `precip_wet_hours`・`precip_total_hours`・`precip_msm_hours`・`precip_moist_hours`・`precip_prob_hours` | 雨天割合の内訳(どの規則で雨と数えたか。README 探索モードの `M`/`湿n`/`確n` の説明)。画面ではセルの中の記号で、答えに使う名前と単位の出典がない |
| `precip_total_mm` | 雨天割合のセルに添える量(`report` の `mm_tag`)。列の名前がない。全日の量は `day_total_precip_mm` を出す |
| 提案の `details`(`native_row`・`cells` など) | スキーマ `biyori-proposal/1` が「窓口は根拠として使わない」としている |
| 提案の `constraints[].text` | 簡易行は「種別はネイティブの簡易行にない」のような内部の言い方。文は `brief` が段階の語から作る |
| 確信度 | 探索モードは出力しない(提案の `uncertainty.confidence.value` は null) |

## その日の順位

| 項目 | 中身 |
|---|---|
| `rank`・`rank_ties` | その日の順位(対象の日・直線 250km 以内・地域で絞った、基準点以上の山の中)と、その順位の山の数。**同点は同じ順位**(100 点が 5 座なら 5 座とも 1 位、次は 6 位)。書いてよい表記は「1位(同点 5 座)」。同点がなければ「1位」「1番目」 |

順位を表す項目はこの 1 つだけ(2026-11-24 に `day_rank` をやめてまとめた)。並び順そのもの(点数 → 危険信号の軽さ → 距離 → 山の ID)は、資料の `facts` の順で表す。

## 古い予報のときの決まった文 `refresh`(利用者の決定 2026-11-25)

`shelf.stale` が真のときだけ入る、新しくする方法の文(GitHub の Actions → collect → Run workflow。入力は `docs/manual-collect.md`)。境目は `config.yaml` の `collect.stale_after_hours`(24 時間)。古さは「丸1日以上前の予報」とも書ける(`data_time` の印を付ける。日数は、実際の古さを超えない数だけ)。

## 比べた結果(`comparisons`。印 `[C1]`〜)

日ごとに、主役の枠の山(`selected_by` が `top`)の中だけで比べる。枠の山が 2 座に満たない日・値のない山がある日・いちばんの山が 2 つ以上ある日は作らない。対象は仮置き(増やすのは、実際の質問を見てから)。

| `kind` | 書いてよい言い方 | 比べる値 |
|---|---|---|
| `ridge_wind_min` | おすすめの候補の中で稜線の風がいちばん弱い | `ridge_wind_ms`(小数のまま) |
| `nearest` | おすすめの候補の中で横浜(出発地)からいちばん近い | 出発地からの直線距離(0.1km) |

## 名指しの山どうしの差(`named_gaps`。印 `[C…]`。比べた結果のあとの番号)

名指しの山が 2 座以上ある質問で、日ごと・2 座ずつの、日中ピークの風速(`day_peak_wind_ms`)の差。値のない山がある組は作らない。書いてよい言い方は「日中ピークの風速の差は ○ m/s」。
差が `config.yaml` の `concierge.brief.small_wind_diff_ms`(仮の値 0.5 m/s。出典なし)以下なら「差はわずか」も書いてよい。`hazard_differs` は、強風の段階が 2 座で違うとき真。

## 危険信号の件数(`hazard_counts`。印 `[N1]`〜)

日ごと(基準点以上の山がある日だけ)に、その日の基準点以上の山(直線 250km 以内・地域で絞った中)のうち、危険信号が「警戒」「危険」の山の数。山のいちばん重い段階で数える(危険と警戒が両方ある山は危険)。

| 項目 | 中身 |
|---|---|
| `above` | 基準点以上の山の数 |
| `all` | 警戒以上の山の数 `total` と、その内訳 `warning`(警戒)・`danger`(危険)。見送りの枠の中と外を合わせた全体 |
| `outside` | 同じ数え方で、見送りの枠の外だけ(答えには書かない。書き手が見るだけ) |
| `say` | 「危険信号が警戒以上の山は 30 座」「このうち危険は 12 座」「危険信号が危険の山は 12 座」「危険信号が警戒の山は 18 座」「基準の70点以上の山は 33 座」 |

種類(強風・低体温症・雷)ごとの数は持たない。

## 主役にできない山

- 点数が基準(70 点。`collect/yamabiyori.py` の `GO_THRESHOLD`、README「行ける」の目安)未満。
- 危険信号が「警戒」「危険」(簡易行は「警戒以上」)。段階の語はヤマビヨリの `report_data.py` の `hazard_class()`(警戒・危険を含むと warning)と `mountain_weather_core.py` の `HAZARD_LEVELS`。
- 「注意」の山は主役にしてよい。すすめるときは `hazards` の文を必ず入れる(照合が止める)。

## 星(段階 3。`stars`・`lines.star_*`・`plans[].frames`)

星の項目は、星の興味の語(`stars`・`milky_way`・`astrophotography`)を渡した質問で、星の棚が使えるときだけ入る。それ以外の資料は 1 バイトも変わらない。
元はホシビヨリの `--json-out`(棚の `hoshibiyori/stars.json`・`milkyway.json`)。対応表は `docs/hoshibiyori-mapping.md`。

| 印 | 項目 | 中身 |
|---|---|---|
| `[S001]`〜 | `stars.facts[]` | 地点と夜。`site_id`・書いてよい名前(`site_index` の `label`。市町村つき)・夜の表記・状態(`status`)・理由・予報の区分(`regime`)・出発地からの直線距離・`requires_lift_access`・順位 `rank`(並びにだけ使い、答えに書かない)・`near`(案で組になる山からの直線距離) |
| `[T1]`〜 | `stars.counts[]` | 夜ごとの状態と件数。`state` = `passed`(250km 以内に条件を通った地点がある)/ `moon`(月の無い時間帯で調べていない = `window_kind: dark`)/ `none_passed`(調べたが無い)/ `not_examined`(調べていない) |

- 資料に入れる地点は、`window_kind` が `moon_free` の夜に `status` が `passed` で、`site_id` があり、出発地から直線 250km 以内のもの。`dark` の夜の `passed`(月が出ている夜に雲と光害だけ通った地点)は使わない(仮置き)。
- 夜ごとに `top_per_night`(5)+ 近くに山がある地点 `with_mountain_per_night`(3)+ 案で山に付く地点。並びは 主軸を先 → ホシビヨリの順位(候補の夜だけにある)→ 直線距離 → `site_id`。
- 値(`values`): 晴れ間の時間帯(`clear_start`〜`clear_end`)・月の無い時間帯(`window_start`〜`window_end`)・晴れ間の長さ(`clear_hours`。0.1 時間の刻み。丸めたら「約」)。名前は、ホシビヨリの画面・README の「晴れ間」「月の無い時間帯」。
- 出していない値: `mean_obstruction`(視界遮蔽雲量。山の雲量と並ぶと読み違えるため)・`alr`(日本で未較正の相対指数)・`score`・`lp_index`・`winter_milky_way`。
- モード: 天の川モードの候補(`finals` + `outlooks`)が `thresholds.milkyway_few_results`(5)より少なければ星空・星座モード、そうでなければ天の川モード(ホシビヨリの画面の案内と同じ決まり。`config.yaml` `concierge.stars.mode_rule`。仮置き)。
- `plans[].frames`: 朝〜日中(山)→ 日中(生き物。段階 4 まで空)→ 夜(星)。順番はコードが決める。

| 文 | 中身 |
|---|---|
| `star_data_time` | 「星の予報は … 時点のものです(… の回)。」24 時間以上前なら「○ 時間前の古い予報です」。山と別の文 |
| `star_mode` | どちらのモードの結果か。語はホシビヨリの `AGENTS.md` 5 章(「星空・星座モード。銀河中心の高度・地形を条件にしない」)と画面(「対象: 天の川銀河中心」) |
| `star_regime` | ECMWF の夜だけ。「…は、ECMWF の予報だけの夜で、雲量は目安です。」(出力の `notes`「forecast_regime が ECMWF の夜の雲量は目安です。」・`AGENTS.md`「ECMWFだけの予報(目安)」) |
| `star_lifts` | `requires_lift_access` の地点ごとに「…はリフト要の地点で、運行は確かめていません。」 |
| `star_skips` | 月の夜・条件を通った地点の無い夜ごとに 1 文。理由の語は「月が出ている」「雲」「光害」「方角」だけ |
| `star_attribution` | 星の帰属(ホシビヨリの README「データ出典と利用上の注意」) |
